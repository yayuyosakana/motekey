# API設計書

## 1. 概要

モテキーで利用するGemini APIの呼び出しフローを定義する。

- **テキスト生成:** Gemini API（テキスト入力 → テキスト出力）
- **画像解析:** Gemini Vision API（画像+テキスト入力 → テキスト出力）

---

## 2. API呼び出しフロー

### 2.1 初回のみ（オンボーディング）

| # | 呼び出し名           | API種別        | 呼び出し元 | 入力                                  | 出力                                       | 保存先                |
|---|----------------------|----------------|------------|---------------------------------------|--------------------------------------------|-----------------------|
| ① | テキストハビット抽出 | Gemini API     | アプリ本体 | ユーザーが入力したLINEの返信サンプル等 | テキストスタイル情報（語尾・口調の特徴）     | App Group (UserDefaults) |

### 2.2 毎回（キーボード使用時）

| # | 呼び出し名                   | API種別             | 入力                                                                             | 出力                                    | 備考                                                           |
|---|------------------------------|---------------------|----------------------------------------------------------------------------------|-----------------------------------------|----------------------------------------------------------------|
| ② | 画面文脈抽出                 | Gemini Vision API   | Broadcast Extensionの最新1フレーム画像（JPEG）                                   | 構造化チャット文脈（話者区別付き）       | LINEのUI構造を認識し相手/自分の発言を区別。画像は送信後即破棄  |
| ③ | アスクユーザーQ1〜Q3一括生成 | Gemini API          | チャット文脈                                                                     | 3問分の質問テキスト + 各3択（計9選択肢） | 1回の呼び出しで3問すべてを生成。分岐なし                      |
| ④ | 返信文生成                   | Gemini API          | チャット文脈 + Q1〜Q3回答 + テキストハビット + リレーション情報 + today_date + システムプロンプト | 返信メッセージ（チップ形式で複数）       | 生成結果はステージバーおよび `全文表示` タブで確認する         |

## 3. API共通設計

### 3.1 通信設定

| 項目               | 値       | 備考                               |
| ------------------ | -------- | ---------------------------------- |
| タイムアウト       | 10秒     | URLSessionのtimeoutInterval                |
| リトライ           | 原則なし（429のみ1回） | タイムアウト時はUIでリトライボタン表示 |
| 同時リクエスト制限 | 1リクエスト | ②→③→④は順次実行（同時送信しない）。③と④の間はユーザー操作（Q1〜Q3回答）を挟む |

### 3.2 エラーハンドリング

| HTTPステータス | 対応                                                  |
| -------------- | ----------------------------------------------------- |
| 200            | 正常処理                                              |
| 400            | リクエスト不正 → ログ出力 + フォールバック            |
| 429            | レート制限 → 2秒待機後にリトライ（1回のみ）          |
| 500系          | サーバーエラー → 「一時的に利用できません」表示       |
| タイムアウト   | リトライボタン表示 or 手入力フォールバック            |

### 3.3 リクエストフォーマット（想定）

#### ③ アスクユーザーQ1〜Q3一括生成のリクエスト

{
  "chat_context": {
    "chat_detected": true,
    "app": "LINE",
    "messages": [
      { "speaker": "partner", "text": "今日買い物行ける？", "date_label": "今日", "time": "18:10" }

③は質問生成専用のため、入力は `chat_context` のみを送信する（`text_habit` / `relation` は送信しない）。

### 3.4 レスポンスフォーマット（想定）

#### ② 画面文脈抽出のレスポンス

```json
{
  "chat_detected": true,
  "app": "LINE",
  "messages": [
    {
      "speaker": "partner",
      "text": "今日買い物行ける？",
      "date_label": "今日",
      "time": "18:10"
    },
    {
      "speaker": "partner",
      "text": "トイレットペーパーなくなりそう",
      "date_label": "今日",
      "time": "18:11"
    },
    {
      "speaker": "me",
      "text": "うーん",
      "date_label": "今日",
      "time": "18:12"
    },
    {
      "speaker": "partner",
      "text": "行けるの？行けないの？",
      "date_label": "今日",
      "time": "18:12"
    }
  ],
  "last_speaker": "partner",
  "last_message": "行けるの？行けないの？"
}
```

会話が検出できない場合は `chat_detected: false` を返す。この場合 `messages` は空配列、`last_speaker` / `last_message` は `null` とする。

#### ③ アスクユーザーQ1〜Q3一括生成のレスポンス

```json
{
  "questions": [
    {
      "question": "買い物に行けますか？",
      "options": [
        { "label": "行ける", "value": "can_go" },
        { "label": "行けない", "value": "cannot_go" },
        { "label": "あとで行く", "value": "later" }
      ]
    },
    {
      "question": "いつ買って帰れそうですか？",
      "options": [
        { "label": "今日の帰りに", "value": "on_the_way_home" },
        { "label": "明日以降に", "value": "tomorrow_or_later" },
        { "label": "今すぐ行ける", "value": "right_now" }
      ]
    },
    {
      "question": "ブランドや種類（ダブル/シングル）の指定はありますか？",
      "options": [
        { "label": "いつものがある", "value": "usual_brand" },
        { "label": "指定なし", "value": "no_preference" },
        { "label": "安ければ何でも", "value": "cheapest" }
      ]
    }
  ]
}
```

`questions` 配列は常に3件、各 `options` 配列は常に3件とする。3問すべてが1回のレスポンスに含まれ、回答による分岐はない。

#### ④ 返信文生成のレスポンス

```json
{
  "chips": [
    { "text": "ごめん、今日仕事で遅くなりそう🥲" },
    { "text": "明日の朝イチで買いに行くね！" },
    { "text": "他に必要なものある？" }
  ]
}
```

`chips` 配列は2〜5件（最大5件）とする。

### 3.5 APIキーの用途別割り当て

MVPではGemini APIキーを4用途に分離して運用する。

| 呼び出し | Info.plistキー | xcconfig変数 |
|----------|----------------|--------------|
| ① テキストハビット抽出 | `GeminiAPIKeyTextHabit` | `GEMINI_API_KEY_TEXT_HABIT` |
| ② 画面文脈抽出（Vision） | `GeminiAPIKeyVisionContext` | `GEMINI_API_KEY_VISION_CONTEXT` |
| ③ アスクユーザーQ1〜Q3一括生成 | `GeminiAPIKeyAskUserQuestion` | `GEMINI_API_KEY_ASK_USER_QUESTION` |
| ④ 返信文生成 | `GeminiAPIKeyReplyGeneration` | `GEMINI_API_KEY_REPLY_GENERATION` |

専用キーが未設定の場合のみ、後方互換として共通キー `GeminiAPIKey`（`GEMINI_API_KEY`）をフォールバック利用してよい。
